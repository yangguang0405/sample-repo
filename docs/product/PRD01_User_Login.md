# PRD：Web端用户登录模块

| 项目 | 内容 |
| ---- | ---- |
| 文档版本 | V1.0 |
| 编写日期 | 2026-10-08 |
| 适用端 | PC Web 网站 |
| 产品类型 | 通用业务后台 / 官网用户系统 |
| 文档目的 | 定义登录页面功能、交互、校验、异常、安全需求，供 UI、前端、后端、测试使用 |

---

## 1 文档概述

### 1.1 产品背景
网站需要用户身份识别，用户可通过**账号密码**、**短信验证码**两种方式完成登录，登录成功进入系统；同时提供注册、找回密码入口，配套基础安全策略防止恶意爆破。

### 1.2 目标用户
网站注册用户

### 1.3 范围

**包含**：登录页面、表单校验、登录请求、会话管理、错误提示、注册/忘记密码跳转、防暴力登录。

**不包含**：用户注册页面、密码重置页面、第三方登录（微信/QQ 等）、管理后台账号管理。

### 1.4 术语定义

| 术语 | 说明 |
| ---- | ---- |
| Token | 登录成功后端返回的身份凭证，前端存储用于后续接口鉴权 |
| 会话有效期 | 勾选记住我，有效期 7 天；不勾选，浏览器关闭会话失效 |
| 验证码 | 短信一次性验证码，有效期 5 分钟 |

---

## 2 业务目标

1. 支持用户两种主流方式登录，降低用户登录门槛
2. 前端 + 后端双层校验，保证账号访问安全
3. 友好的交互提示，减少用户操作困惑
4. 限制恶意尝试，防止账号暴力破解

---

## 3 功能需求

### 3.1 页面整体结构
页面分为两个 Tab：【账号密码登录】（默认激活）、【短信验证码登录】。

页面元素：
1. 模块标题：用户登录
2. Tab 切换组件
3. 表单输入区域
4. 错误提示区域（统一展示，红色文字）
5. 记住我复选框（仅账号密码 Tab 可见）
6. 登录提交按钮
7. 辅助链接：立即注册｜忘记密码

### 3.2 账号密码登录 Tab

#### 3.2.1 输入项

| 字段 | 说明 | 前端校验规则 |
| ---- | ---- | ---- |
| 账号 | 手机号 / 用户名 | 非空；手机号则校验 11 位数字格式；用户名支持字母数字下划线 |
| 密码 | 登录密码 | 非空；长度 6~20 位 |

#### 3.2.2 交互规则
1. 密码框右侧有眼睛图标：点击切换明文 / 密文显示密码
2. 记住我复选框：默认不勾选；勾选则登录凭证有效期 7 天；不勾选，浏览器关闭失效
3. 提交方式：点击登录按钮 / 输入框回车提交表单
4. 提交时按钮置灰，防止重复点击，加载状态提示"登录中..."

#### 3.2.3 后端校验逻辑
1. 账号不存在：提示"该账号未注册，请先注册"
2. 密码错误：提示"账号或密码错误"；累计错误次数 +1
3. 连续密码错误达到 5 次：锁定账号 10 分钟，提示"密码错误次数过多，请10分钟后重试"

### 3.3 短信验证码登录 Tab

#### 3.3.1 输入项

| 字段 | 说明 | 前端校验规则 |
| ---- | ---- | ---- |
| 手机号 | 用户注册手机号 | 非空，必须 11 位数字 |
| 短信验证码 | 短信收到的数字验证码 | 非空，4~6 位数字 |

#### 3.3.2 获取验证码交互
1. 获取验证码按钮：手机号校验通过后才可点击；手机号非法时按钮置灰不可点
2. 点击发送：后端发送短信，按钮开始 60s 倒计时，倒计时期间按钮不可点击，显示"60s后重新获取"
3. 短信频率限制：同一手机号 1 分钟最多 1 条，1 小时最多 5 条验证码
4. 验证码有效期 5 分钟，过期失效

#### 3.3.3 后端校验逻辑
1. 手机号未注册：提示"该手机号尚未注册，请先注册"
2. 验证码错误：提示"验证码不正确，请重新输入"
3. 验证码已过期：提示"验证码已失效，请重新获取"

### 3.4 辅助跳转链接
1. 立即注册：点击跳转【用户注册页面】；登录前有来源页面，注册成功后回跳原页面
2. 忘记密码：点击跳转【密码重置页面】

### 3.5 登录成功逻辑
1. 后端返回 Token，前端存储（Cookie / LocalStorage，由技术方案确定）
2. 跳转规则：
   - 如果用户是从某个业务页面跳转至登录页 → 登录成功返回原页面
   - 直接访问 /login 登录页 → 登录成功跳转到网站首页
3. 页面刷新后保持登录状态（受记住我选项控制）

### 3.6 退出登录（配套）
任意页面右上角退出登录按钮：清除本地 Token，销毁后端会话，跳转登录页。

## 4 异常场景 & 错误提示

| 场景 | 页面提示文案 |
| ---- | ---- |
| 前端表单为空 | 请输入账号/手机号，请输入密码/验证码 |
| 网络请求失败 | 网络异常，请检查网络后重试 |
| 账号密码错误 | 账号或密码错误 |
| 账号锁定 | 密码错误次数过多，请10分钟后重试 |
| 验证码错误 | 验证码不正确，请重新输入 |
| 验证码过期 | 验证码已失效，请重新获取 |
| 手机号未注册 | 该手机号尚未注册，请先注册 |
| 发送短信过于频繁 | 获取验证码过于频繁，请稍后再试 |

> 规则：所有错误提示在页面表单上方统一展示，不使用浏览器 alert 弹窗。

## 5 非功能需求

### 5.1 性能
1. 登录接口响应时间 ≤ 500ms（正常网络）
2. 页面加载完成时间 ≤ 1.5s

### 5.2 兼容性
PC 端：Chrome、Edge、Firefox 主流浏览器，支持现代版本

### 5.3 安全需求
1. 页面必须 HTTPS 访问
2. 密码不能明文传给后端，前端做摘要处理（SHA256）
3. 前端输入增加防 XSS 过滤
4. 接口增加防重放、防重复提交
5. 短信验证码接口增加限流，防止恶意刷短信
6. 后端校验账号、验证码，**不能只依赖前端校验**
7. Token 设置合理过期时间，退出登录后端立即失效 Token

### 5.4 UI & 交互
1. 表单输入框聚焦高亮，输入失焦实时校验
2. 按钮置灰状态区分可点击 / 不可点击
3. 页面简洁，错误提示红色，成功提示绿色

## 6 埋点需求（可选）

1. 登录页面 PV
2. Tab 切换事件：切换到账号密码登录 / 短信验证码登录
3. 登录提交次数、登录成功次数、登录失败次数
4. 点击【立即注册】、【忘记密码】事件

---

## 7 接口需求（简要）

1. 登录接口 `POST /api/login`
   - 参数：登录类型、账号、密码 / 验证码
   - 返回：code、msg、token、用户基础信息
2. 发送短信接口 `POST /api/sms/send`
   - 参数：手机号
   - 返回：code、msg

---

## 8 测试要点

1. 前端表单各种空值、非法格式校验
2. 账号密码登录：正确登录、密码错误、账号锁定场景
3. 短信登录：发送验证码倒计时、频率限制、验证码过期
4. 记住我功能验证
5. 登录成功回跳原页面逻辑
6. 网络异常场景
7. 安全：暴力尝试、XSS、抓包查看明文密码
