## 1 文档概述

### 1.1 产品背景
网站需要用户身份识别，用户可通过**账号密码**、**短信验证码**两种方式完成登录，登录成功进入系统；同时提供注册、找回密码入口，配套基础安全策略防止恶意爆破。

### 1.2 目标用户
网站注册用户

### 1.3 范围

**包含**：登录页面、表单校验、登录请求、会话管理、错误提示、注册/忘记密码占位入口、防暴力登录及共享布局退出。

**不包含**：用户注册页面、密码重置页面、第三方登录（微信/QQ 等）、管理后台账号管理。

#### 本期交付与依赖

本次澄清沿用 Issue #7 的完整登录目标：本期交付前端、认证后端、持久化账号/会话/限流存储，以及真实短信供应商集成；不将 mock 登录视为功能完成。该范围为本 PR 提交评审的范围选择。

- 注册与找回密码仅提供 3.4 的占位行为，不依赖尚不存在的页面；退出功能按 3.6 在共享布局交付。
- 自动化测试与本地开发可使用实现相同契约的 mock 短信适配器；生产不得启用固定验证码或 mock 认证。
- 功能验收使用独立 HTTPS 集成环境、真实认证与存储，并通过真实短信服务向受控测试手机号完成至少一轮发送、登录、会话查询和退出。限流、过期、失败等场景可通过可控时钟及短信故障模拟测试。
- 测试账号由受控初始化脚本预置用户名、手机号和密码哈希，不新增用户注册接口。短信供应商、凭据、发送模板、受控手机号及项目发送预算由部署方提供，接入方式由技术方案记录；缺失时真实短信验收为阻塞，不能以 mock 通过替代。
- Issue #7 仅在本期真实服务验收完成后关闭；本 PR 只确认需求，不交付应用功能。

### 1.4 术语定义

| 术语 | 说明 |
| ---- | ---- |
| Token | 服务端生成的不可预测会话标识，仅通过 HttpOnly Cookie 交给浏览器，不暴露给前端脚本 |
| 会话有效期 | 记住我为固定 7 天；默认使用会话 Cookie，服务端闲置 30 分钟或创建后 12 小时到期，详见 3.5 |
| 验证码 | 短信一次性验证码，有效期 5 分钟 |

## 2 业务目标

1. 支持用户两种主流方式登录，降低用户登录门槛
2. 前端 + 后端双层校验，保证账号访问安全
3. 友好的交互提示，减少用户操作困惑
4. 限制恶意尝试，防止账号暴力破解

## 3 功能需求

### 3.1 页面整体结构
页面分为两个 Tab：【账号密码登录】（默认激活）、【短信验证码登录】。

页面元素：
1. 模块标题：用户登录
2. Tab 切换组件
3. 表单输入区域
4. 错误提示区域（统一展示，红色文字）
5. 记住我复选框（仅账号密码 Tab 可见）
6. 登录提交按钮
7. 辅助链接：立即注册｜忘记密码

### 3.2 账号密码登录 Tab

#### 3.2.1 输入项

| 字段 | 说明 | 前端校验规则 |
| ---- | ---- | ---- |
| 账号 | 手机号 / 用户名 | 非空；手机号则校验 11 位数字格式；用户名支持字母数字下划线 |
| 密码 | 登录密码 | 非空；长度 6~20 位 |

#### 3.2.2 交互规则
1. 密码框右侧有眼睛图标：点击切换明文 / 密文显示密码
2. 记住我复选框：默认不勾选；勾选则会话固定有效 7 天；不勾选采用 3.5 的默认会话规则
3. 提交方式：点击登录按钮 / 输入框回车提交表单
4. 提交时按钮置灰，防止重复点击，加载状态提示"登录中..."

#### 3.2.3 后端校验逻辑
1. 账号不存在、密码错误或账号已锁定，均返回 `401 AUTH_INVALID`，提示“账号或密码错误，或暂时无法登录，请稍后重试”；不返回是否注册、锁定状态、剩余次数或账号级解锁时间。
2. 同一账号的用户名与手机号共用错误计数；连续密码错误 5 次后禁止密码登录 10 分钟。锁定期间即使密码正确也不建立会话。
3. 计数、重置、并发和 IP 限制按 3.7 执行。短信登录不受密码锁定影响，但有独立的尝试次数和 IP 限制。

### 3.3 短信验证码登录 Tab

#### 3.3.1 输入项

| 字段 | 说明 | 前端校验规则 |
| ---- | ---- | ---- |
| 手机号 | 用户注册手机号 | 非空，必须 11 位数字 |
| 短信验证码 | 短信收到的数字验证码 | 非空，固定 6 位数字 |

#### 3.3.2 获取验证码交互
1. 手机号校验通过后获取验证码按钮才可点击。请求期间禁用按钮，避免重复提交。
2. 服务端受理后返回 `202 SMS_ACCEPTED`，统一提示“如该手机号可用于登录，将收到验证码”，开始 60s 倒计时；受理不代表短信已送达。
3. 未注册手机号返回相同响应和倒计时，不发送短信。注册状态不通过响应体、HTTP 状态或手机号级限流行为暴露。
4. 同一手机号滚动 60 秒最多受理 1 次、滚动 1 小时最多受理 5 次；按 3.7 叠加 IP 限流。
5. 验证码从生成时起 5 分钟有效；供应商确认接受新短信后激活新码、使旧码失效，只保留最新码；供应商明确拒绝时保留旧码。网络超时等结果不明时用同一业务请求 ID 查询或幂等重试，确认前不激活新码；迟到结果不得覆盖更新的验证码。

#### 3.3.3 后端校验逻辑
1. 手机号未注册、验证码错误、过期、已使用或尝试次数耗尽，均返回 `401 AUTH_INVALID`，提示“手机号或验证码无效，请重新获取验证码后重试”。
2. 每个验证码最多校验失败 5 次，第 5 次失败后失效；验证码正确时原子消费，并创建会话，并发提交仅一次成功。
3. 验证码在登录接口内校验，不提供独立的验证码验证接口。短信登录固定采用默认会话规则，不提供记住我。

### 3.4 辅助入口
1. 本期保留“立即注册”“忘记密码”入口，点击后在表单上方分别提示“注册功能暂未开放”“密码重置功能暂未开放”；不跳转空页面或死链。
2. 注册及密码重置流程、注册成功回跳均不在本期验收范围；待对应能力上线后另行调整入口。

### 3.5 登录成功与会话
1. 采用同源服务端会话。服务端通过 `Set-Cookie` 设置 `__Host-session`，属性为 `HttpOnly; Secure; SameSite=Lax; Path=/`，不设置 `Domain`。响应 JSON 不返回 Token，禁止在 LocalStorage、SessionStorage 或 URL 中存储会话标识。
2. 账号密码登录且 `rememberMe=true`：Cookie 设置 `Max-Age=604800`，服务端绝对有效期为创建后 7 天，不滑动续期。
3. 默认及短信登录：Cookie 不设置 `Expires` / `Max-Age`；服务端闲置 30 分钟或创建后 12 小时到期，以先到者为准。有效的鉴权请求更新最后活动时间，前端不通过心跳延长会话。
4. 普通关闭浏览器按会话 Cookie 语义处理，但浏览器恢复会话可能保留 Cookie，服务端也无法可靠检测浏览器关闭；因此不承诺“关闭浏览器立即销毁服务端会话”。严格退出使用 3.6。
5. 每次成功登录生成新会话标识，并撤销该浏览器携带的旧会话，避免会话固定；本期不提供 refresh token 或独立续期接口。
6. 页面刷新通过 `GET /api/session` 恢复当前用户状态；会话到期或撤销返回 `401 SESSION_EXPIRED`，清理页面用户状态并跳转登录页。其他设备会话不因本设备退出而撤销。
7. 来源页面回跳：仅允许以单个 `/` 开头的站内相对路径，按站点路由白名单校验。拒绝绝对 URL、`//`、反斜杠、控制字符、编码或多重编码绕过、认证页循环及 `/api` 路径；客户端与服务端均验证，服务端为最终依据。
8. 来源路径及生成时间由服务端保存或签名，有效期 30 分钟，登录成功后消费；篡改、过期、无效、无权限或不存在的路径均回退 `/`。直接访问登录页也回到 `/`；回跳不能替代目标页面的权限校验。

### 3.6 退出登录
1. 本期在现有共享应用布局的已登录区域提供退出按钮，首页可验收；登录页及未登录状态不展示，无需逐页新增按钮或创建其他业务页面。
2. 调用 `POST /api/logout`；服务端撤销当前会话并以相同 Cookie 属性、`Max-Age=0` 清除 Cookie，成功后清理前端用户状态并跳转登录页。
3. 接口幂等，无会话或已过期也返回成功；网络失败提示重试，不能仅清空前端状态就宣称服务端已退出。

### 3.7 限流与锁定口径

以下为本期默认值，可通过服务端配置调整；验收使用这些默认值。时间和计数均由服务端决定，跨实例共享存储并原子更新，不能依赖浏览器倒计时。

| 维度 | 限制与计数规则 | 重置规则 |
| ---- | ---- | ---- |
| 密码账号 | 按内部账号 ID 汇总用户名/手机号的连续密码错误；第 5 次失败起锁定密码登录 10 分钟 | 成功的密码登录或锁定到期清零；短信成功不清零；锁定期间请求不延长锁定 |
| 不存在的账号 | 按规范化输入使用有期限的影子计数，模拟同样的失败/锁定行为；不创建用户 | 与真实账号相同，闲置 24 小时回收影子记录 |
| 登录来源 IP | 两种登录方式合计，滚动 1 分钟最多 30 次请求，无论结果如何均计数 | 成功不重置，窗口自然释放 |
| 短信手机号 | 滚动 60 秒最多 1 次，滚动 1 小时最多 5 次已受理请求；注册与未注册号码同样计数 | 成功登录、短信发送或供应商失败均不重置/返还已受理配额，窗口自然释放 |
| 短信来源 IP | 滚动 1 分钟最多 5 次，滚动 1 小时最多 20 次受理，跨手机号合计 | 窗口自然释放，不随登录或发送成功重置 |
| 验证码 | 每个码最多 5 次失败校验 | 新码建立独立计数；旧码同时失效 |

1. 手机号去首尾空格，本期仅支持中国大陆 11 位手机号；用户名去首尾空格并区分大小写精确匹配，密码不裁剪或改写。身份解析后必须按同一账号 ID 计数。
2. IP 只来自受信任反向代理解析后的客户端地址，不直接信任任意 `X-Forwarded-For`。IP 限流先于账号鉴权，避免账号状态影响限流响应。
3. 手机号与 IP 短信配额需一起原子预留；并发超额请求不发送。供应商重试使用同一业务请求 ID 幂等发送，不新增短信和配额消费。
4. 限流统一返回 `429 RATE_LIMITED` 与 `Retry-After` 秒数；密码账号锁定仍返回通用 `AUTH_INVALID`，不返回账号级倒计时。
5. 真实短信环境须配置项目级每日发送硬上限及费用告警，阈值由部署方按预算设定并记录；未配置不得启用真实发送。触及项目上限或基础设施整体不可用统一返回 `503 SERVICE_UNAVAILABLE`，与手机号注册状态无关。
6. 不存在账号也执行等价密码哈希验证；短信采用异步受理。对注册/未注册、锁定/未锁定失败响应进行统计时延检查，不因提前返回形成明显枚举通道。

## 4 异常场景 & 错误提示

| 场景 | 页面提示文案 |
| ---- | ---- |
| 前端表单为空 | 请输入账号/手机号，请输入密码/验证码 |
| 网络请求失败 | 网络异常，请检查网络后重试 |
| 账号不存在、密码错误或账号锁定 | 账号或密码错误，或暂时无法登录，请稍后重试 |
| 手机号未注册、验证码错误/过期/已使用/次数耗尽 | 手机号或验证码无效，请重新获取验证码后重试 |
| 短信请求受理（包括未注册手机号） | 如该手机号可用于登录，将收到验证码 |
| 请求超过频率限制 | 操作过于频繁，请稍后再试 |
| 会话失效 | 登录状态已失效，请重新登录 |
| 服务整体不可用 | 服务暂时不可用，请稍后重试 |

> 规则：所有错误提示在页面表单上方统一展示，不使用浏览器 alert 弹窗。

## 5 非功能需求

### 5.1 性能
1. 生产构建在独立验收环境测量，固定 2 vCPU / 4 GiB 应用实例、同区域数据库与会话存储；报告记录部署版本、区域、数据库规格及数据量，不使用开发服务器。
2. 登录接口：预热 1 分钟后，以 10 并发持续 5 分钟，至少采集 1,000 次有效请求；从负载客户端发出请求到完整响应的 P95 ≤ 500ms，客户端到服务端 RTT ≤ 20ms。分别报告密码登录与验证码登录，包含数据库、密码哈希、会话写入时间；使用足够多测试账号和来源地址避免压测触发限流，另测限流行为。
3. 登录页：固定桌面 Chrome 稳定版并记录版本，4 核 / 8 GiB 测试机，视口 1440×900，下载 10 Mbps、上传 5 Mbps、RTT 40ms；生产构建、清空缓存，至少 30 次访问，LCP P95 ≤ 1.5s。表单可操作时间单独记录，不把 LCP 等同于所有资源加载完成。
4. `POST /api/sms/send` 仅度量请求校验及异步入队，沿用接口 P95 ≤ 500ms；第三方短信投递不计入此指标，单独记录受理到送达的成功率和耗时。登录接口只验证本地验证码，不等待供应商。
5. 性能阈值是指定环境的 P95 目标，不是每次请求上限；报告同时列出样本数、P50/P95/P99 和错误率。mock 数据不能证明真实服务性能达标。

### 5.2 兼容性
PC 端：Chrome、Edge、Firefox 主流浏览器，支持现代版本

### 5.3 安全需求
1. 页面及接口必须 HTTPS。密码作为 TLS 加密请求体字段传输，不做前端 SHA-256 预哈希；前端摘要不能替代安全传输或服务端密码存储。
2. 服务端使用带独立盐的 Argon2id 存储密码（最低 memory=19 MiB、iterations=2、parallelism=1，结合部署性能调优），禁止保存原始密码或使用单轮 SHA-256/MD5。测试账号也使用相同存储方式。
3. 会话按 3.5 使用 HttpOnly Cookie；所有状态变更接口（含登录、短信和退出）校验同源 `Origin` 并要求与匿名/已登录会话绑定的 CSRF token，不将 SameSite 作为唯一 CSRF 防线。
4. 服务端严格校验输入结构与长度，输出按上下文编码，禁止将用户输入直接注入 HTML；前端校验只改善交互，不能代替后端安全校验，也不以过滤密码字符防 XSS。
5. 验证码使用安全随机数生成、服务端安全存储、短时有效且一次消费；同一密码请求无法仅靠前端摘要实现防重放，密码攻击依靠 TLS、CSRF 防护及服务端限流约束。
6. 密码、验证码、会话 Cookie 不写入 URL、日志、埋点或错误报告；会话和认证响应设置 `Cache-Control: no-store`。安全日志可记录内部失败原因，但不得通过公开接口返回。
7. 账号存在性不通过错误码、文案、响应结构、锁定信息或明显时延差异暴露；具体规则见 3.2、3.3、3.7。

依据：[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。本节修订 Issue #7 及 V1.0 中“前端摘要”和“区分未注册账号”的要求，V1.1 同时将“关闭浏览器即失效”澄清为 3.5 的可实现语义，并将辅助链接改为 3.4 的占位行为。这些是对原需求的显式修订，以本 PR 合并后的 V1.1 为验收基线。

### 5.4 UI & 交互
1. 表单输入框聚焦高亮，输入失焦实时校验
2. 按钮置灰状态区分可点击 / 不可点击
3. 页面简洁，错误提示红色，成功提示绿色

## 7 接口与会话契约

同源 JSON 接口，服务端校验所有字段；响应结构为 `{code, msg, data}`，失败时 `data=null`。前端依据稳定 `code` 映射文案，不解析 `msg`。所有 POST 请求须携带 `X-CSRF-Token`。

| 接口 | 请求 | 成功响应与行为 |
| ---- | ---- | ---- |
| `GET /api/csrf` | 无 | `200 OK`，`data={csrfToken}`；设置或复用绑定该 token 的匿名/登录上下文，响应不可缓存 |
| `POST /api/login`（密码） | `{type:"password", account, password, rememberMe:false}`；rememberMe 可选、默认 false；可附服务端签名的 `returnState` | `200 OK`，`data={user:{id,displayName},expiresAt,redirectTo}`；Set-Cookie 建立会话，不返回 Token |
| `POST /api/login`（短信） | `{type:"sms", phone, code}`；可附 `returnState`；不接受 rememberMe=true | 同上，验证码校验与消费在此完成，采用默认会话 |
| `POST /api/sms/send` | `{phone}` | `202 SMS_ACCEPTED`，`data={retryAfter:60}`；异步受理，注册与未注册手机号响应一致 |
| `GET /api/session` | 浏览器自动携带会话 Cookie | `200 OK`，`data={user:{id,displayName},expiresAt}`；expiresAt 为当前最早到期时间，UTC ISO 8601 |
| `POST /api/logout` | `{}` | `200 OK`，`data=null`；撤销当前会话并清 Cookie；已失效会话也成功 |

登录页服务端接收候选 `returnUrl`，按 3.5 校验后签发包含路径与生成时间的 `returnState`；前端原样带入登录请求。无该字段或校验失败不阻止有效凭据登录，只回退首页。登录成功后旧 CSRF 上下文失效，下一次 POST 前重新获取 CSRF token；过期会话的退出请求可先取得新的匿名 CSRF 上下文再重试。

| HTTP / code | 适用场景 |
| ---- | ---- |
| `400 VALIDATION_ERROR` | 字段缺失、格式错误或不支持的登录类型，不涉及账号存在性 |
| `401 AUTH_INVALID` | 密码或短信认证失败，包括锁定及未注册；文案按登录类型统一 |
| `401 SESSION_EXPIRED` | 会话查询或其他受保护接口缺少有效会话 |
| `403 CSRF_INVALID` | Origin / CSRF 校验失败，不处理登录、发送或退出操作 |
| `429 RATE_LIMITED` | IP / 手机号请求配额超限，附 `Retry-After` 响应头 |
| `503 SERVICE_UNAVAILABLE` | 整体认证存储、短信队列或项目发送能力不可用；不暴露内部详情 |

锁定计数、验证码和会话存储属于本期服务端契约，无需向客户端开放独立接口。已受理后的单条短信供应商失败仅在服务端记录和受控重试，客户端不获知号码是否注册；倒计时结束后允许按配额重新申请。

## 8 验收要点

1. 表单空值、格式、回车提交、显隐密码、Tab 切换及重复提交保护；短信固定 6 位，错误统一在表单上方显示。
2. 注册与未注册账号、错误密码及锁定账号使用相同 HTTP 状态、code 和文案；短信失败与受理也验证账号存在性不泄露。
3. 第 5 次密码错误锁定；用户名和手机号共享计数；锁定中正确密码仍失败，10 分钟后恢复，成功密码登录清零；短信成功不清零。
4. 验证手机号/IP 两维限流、滚动时间窗口边界、多实例并发、供应商失败计数和幂等重试；修改前端倒计时不能绕过后端限制。
5. 验证码 5 分钟到期、重新发送使旧码失效、5 次错误后失效、重复/并发正确提交仅成功一次。
6. 验证默认会话的闲置/绝对到期、记住我固定 7 天不续期、短信默认会话、刷新恢复、旧会话替换、服务端撤销及幂等退出。关闭浏览器测试关闭会话恢复功能，同时记录恢复模式的产品限制。
7. 浏览器脚本和响应 JSON 无法读取会话标识；Cookie 属性、CSRF、日志脱敏、缓存及密码哈希存储符合 5.3；正常 TLS 解密后的请求体含密码字段属于预期，不以“前端摘要”作为验收项。
8. returnUrl 测试有效来源、30 分钟过期、篡改、外站、协议相对地址、反斜杠、编码绕过、无权限、不存在路径及登录循环，失败均回首页。
9. 注册/找回密码入口展示明确的暂未开放提示；共享布局仅已登录时显示退出；网络失败不得假报退出成功。
10. 按 5.1 记录接口、页面和短信投递的独立指标及环境，不以 mock 性能替代真实服务结论。
